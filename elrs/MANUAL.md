# ExpressLRS Automation Suite: Technical Manual

## Overview
The `elrs_tool.py` is a Python-based automation wrapper designed to streamline the compilation and deployment of ExpressLRS firmware for **RadioMaster RP1/RP2** receivers. It abstracts the complexities of PlatformIO environments and manual configuration files.

## Hardware Specifics

### Hardware Selection Flag (`--hw`)
The tool provides a `--hw` flag to switch between RadioMaster receiver models. This flag automatically injects the correct `board_config` into the PlatformIO environment to ensure correct pin mappings for antennas and LEDs.

- **RP2 (Default):** Use `--hw rp2` (or omit). Optimized for the ceramic patch antenna.
- **RP1:** Use `--hw rp1`. Optimized for the external U.FL antenna.

Example:
```bash
./elrs_tool.py build --hw rp1
```

## System Architecture

### 1. Environment Management
- **Setup:** The `setup.sh` script initializes a localized Python virtual environment (`venv`).
- **Dependencies:** PlatformIO Core is installed within this venv to avoid system-wide conflicts.
- **Auto-Detection:** `elrs_tool.py` automatically detects if it is being run alongside a `./venv/` directory and prioritizes the localized `pio` executable.

### 2. The Build Pipeline
When running `./elrs_tool.py build`:
1. **Source Control:** The tool clones or updates the official ExpressLRS repository.
2. **Version Logic:** 
   - If a version is provided (e.g., `--version 3.5.6`), it performs a hard checkout.
   - If no version is provided, it fetches tags and identifies the latest stable release (matching `v*`).
3. **Hardware Mapping:**
   - The tool currently defaults to the `Unified_ESP8285_2400_RX_via_UART` target.
   - This target is the standard for the ESP8285-based RP1/RP2 hardware in the ExpressLRS v3.x unified framework.
4. **Firmware Customization:** It dynamically generates a `user_defines.txt` in the source directory with:
   - `-DSERIAL_PROTOCOL_MAVLINK`
   - `-DUART_BAUD=460800`
   - (Optional) Binding phrase.
5. **Compilation:** Executes `pio run` with the target environment.
6. **Artifact Management:** Successful builds are copied to `backups/` with a timestamped filename (e.g., `elrs_3.5.6_20260125_120000.bin`).

### 3. Flashing Mechanisms

#### WiFi Flash (`flash-wifi`)
- **Discovery:** Attempts to verify the "ExpressLRS RX" SSID connection.
- **Compression:** ESP8285-based receivers (RP1/RP2) require the firmware to be Gzipped (`.bin.gz`) for OTA updates to fit in memory. The tool handles this automatically during the build step.
- **Deployment:** Uses `curl` to POST the compressed binary to the receiver's internal update server at `10.0.0.1`.

#### Serial Flash (`flash-serial`)
- **Passthrough:** Uses PlatformIO's built-in upload logic.
- **Flexibility:** Allows specifying a `--port` (e.g., `/dev/ttyACM0`) for direct or FC-passthrough connections.

## Configuration Reference

| Parameter | Default Value | Description |
|-----------|---------------|-------------|
| Target | `Unified_ESP8285_2400_RX_via_UART` | Hardware environment |
| Serial Protocol | `MAVLINK` | Protocol for FC communication |
| Baud Rate | `460800` | UART communication speed |
| Version | Latest Stable Tag | ExpressLRS source version |

## Troubleshooting

### "pio: command not found"
Ensure you have run `./setup.sh` or that your virtual environment is active. The tool looks for `./venv/bin/pio` relative to its execution path.

### Build Failures
Check the `ExpressLRS/src/user_defines.txt` file generated by the tool. Ensure no conflicting defines are present.

### WiFi Flash Timeout
Ensure your machine is successfully connected to the `ExpressLRS RX` network and that the receiver is in WiFi mode (indicated by a fast LED blink).
